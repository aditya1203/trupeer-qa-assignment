# Part 3 integrates an LLM into the test infrastructure to evaluate
non-deterministic output generated by Trupeer's AI script modification
feature.

Unlike traditional UI assertions, AI-generated text cannot reliably be
validated against one exact expected string.

The LLM therefore acts as a semantic test oracle.

---

## Approach

The test performs the following workflow:

```text
Login
  ↓
Open existing video
  ↓
Capture original script
  ↓
Send prompt to Trupeer AI
  ↓
Capture AI-generated script
  ↓
Send Original + Prompt + AI Output to LLM Judge
  ↓
Evaluate against QA rubric
  ↓
Generate structured result
  ↓
Generate JSON evaluation report

Test Prompts

The test evaluates multiple modification scenarios:

Make it more engaging
Make this more professional
Add a call to action at the end
Translate to Spanish

For every prompt, the test captures the actual AI-generated script from
the Trupeer UI.

LLM Judge

The LLM evaluation is implemented in:

services/LLMJudge.js

Groq is used as the LLM provider.

The judge receives:

Original script
User prompt
AI-generated script
Structured evaluation criteria
Evaluation Criteria

Each generated script is evaluated using four criteria.

1. Intent Match

Does the modified script satisfy the intent of the user's prompt?

2. Coherence and Grammar

Is the generated script understandable, coherent, and grammatically
correct?

3. Information Preservation

Does the generated script preserve the important information from the
original script?

4. Meaningful Change

Does the generated script make an appropriate change based on the
requested modification?

Structured LLM Response

The LLM is instructed to return structured JSON.

Example:

{
  "overallPass": true,
  "confidence": 0.95,
  "criteria": {
    "intent": true,
    "coherence": true,
    "preservation": true,
    "meaningfulChange": true
  },
  "summary": "Evaluation summary"
}

The test parses the response and uses overallPass as the semantic
assertion.

JSON Evaluation Report

The test generates:

ai-evaluation-report.json

The report contains:

Execution timestamp
Total number of prompts
Number of passed prompts
Number of failed prompts
Overall result
Overall confidence
Per-prompt result
Per-criterion pass/fail
Evaluation summary

Example:

{
  "testName": "AI Script Modification Evaluation",
  "overallResult": "PASS",
  "totalPrompts": 4,
  "promptsPassed": 4,
  "promptsFailed": 0,
  "overallConfidence": 0.95
}

A sample evaluation report is included in:

part3/ai-evaluation-report.json
Running Part 3

From the project root:

Install dependencies
npm install
Run AI validation
npm run validate

The command executes the Part 3 validation flow.

Environment Variables

Create a .env file in the project root:

TRUPEER_EMAIL=your-trupeer-email
TRUPEER_PASSWORD=your-trupeer-password
GROQ_API_KEY=your-groq-api-key

The API key and credentials must not be hardcoded in the source code.

Test Flow

The test:

Logs into Trupeer.
Opens an existing video.
Verifies the editor.
Captures the original script.
Sends multiple prompts to Trupeer AI.
Captures each generated script.
Sends the original script, prompt, and generated script to Groq.
Evaluates the generated script using the QA rubric.
Produces per-prompt results.
Produces an overall evaluation summary.
Generates a JSON evaluation report.
Deterministic + Semantic Validation

Part 3 intentionally combines two validation approaches.

Deterministic validation

Playwright verifies that the generated script is different from the
original:

expect(modifiedScript.trim()).not.toBe(originalScript.trim());
Semantic validation

The LLM judge evaluates whether the generated output actually satisfies
the requested modification.

Playwright Assertion
        +
LLM Semantic Evaluation
        =
AI-Aware Test Validation

This avoids relying on a single exact expected string for
non-deterministic AI output.

CI Gating Strategy

The LLM judge should not be treated as an absolute source of truth.

A potential CI gating strategy would require:

overallPass = true
Confidence >= 0.90
All critical criteria = true

Lower-confidence results can be routed for human review instead of
automatically failing the pipeline.

If the LLM judge disagrees with a human reviewer, the human review should
take precedence.

Such disagreements can be recorded and used to improve:

Evaluation criteria
LLM prompts
Confidence thresholds
CI gating rules
